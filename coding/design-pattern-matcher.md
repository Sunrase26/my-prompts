# Подбор паттернов проектирования (Design Patterns)

**Когда использовать:** Когда пишешь сложную логику и понимаешь, что задача типичная, но не можешь вспомнить, какой именно паттерн (GoF) здесь лучше всего применить, чтобы код остался масштабируемым.

**Промпт:**
> Выступи в роли Senior Software Architect. У меня есть следующая архитектурная задача: 
> 
> [ОПИСАТЬ ЗАДАЧУ СВОИМИ СЛОВАМИ, например: мне нужно, чтобы при изменении статуса заказа в базе, автоматически отправлялись email, пуш-уведомление и обновлялась статистика, но я не хочу жестко связывать эти классы между собой].
> 
> Мой язык программирования: [ВСТАВИТЬ ЯЗЫК, например: Java / TypeScript / Python].
> 
> 1. Посоветуй 1-2 классических паттерна проектирования, которые идеально решают мою задачу (например, Observer, Factory, Strategy и т.д.).
> 2. Объясни простым языком, почему именно они подходят лучше всего.
> 3. Напиши минималистичный пример кода (скелет классов), показывающий реализацию выбранного паттерна для моей конкретной задачи.
