# Генератор сообщений для коммитов (Conventional Commits)

**Когда использовать:** Когда внес кучу изменений в код, и нужно написать красивый и понятный commit message, чтобы коллеги (или преподаватель) поняли, что именно ты сделал.

**Промпт:**
> Ты — опытный разработчик. Я отправлю тебе список моих изменений (или результат команды `git diff`). 
> 
> Мои изменения:
> [ОПИСАТЬ СВОИМИ СЛОВАМИ ИЛИ ВСТАВИТЬ GIT DIFF, например: поправил баг в корзине, обновил версию реакта в package.json, добавил новый компонент кнопки]
> 
> Напиши для этого 3 варианта сообщений коммита по стандарту "Conventional Commits".
> 
> Правила:
> 1. Формат: `<тип>(<область>): <краткое описание>`.
> 2. Типы на выбор: feat, fix, docs, style, refactor, test, chore.
> 3. Описание должно быть в повелительном наклонении (добавить, исправить, обновить).
> 4. Если изменения слишком разные, предложи разбить их на два отдельных коммита и напиши сообщение для каждого.
