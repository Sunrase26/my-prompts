# Генератор описаний для Pull Request (PR)

**Когда использовать:** Когда ты завершил задачу, залил ветку на GitHub и создаешь Pull Request, чтобы твой код влили в основную ветку (`main`).

**Промпт:**
> Ты — опытный Tech Lead. Я создаю Pull Request в репозиторий проекта. 
> 
> Вот список того, что я сделал:
> [ОПИСАТЬ СВОИМИ СЛОВАМИ, например: добавил валидацию формы регистрации, исправил баг с вылетом при пустом пароле, обновил библиотеку axios]
> 
> Напиши профессиональное и структурированное описание для моего Pull Request в формате Markdown.
> 
> Обязательно включи следующие секции:
> 1. **Описание изменений** (What changed) — кратко и по делу.
> 2. **Мотивация** (Why) — зачем это было нужно (например, закрывает баг или добавляет фичу).
> 3. **Как тестировать** (How to test) — пошаговая инструкция для ревьюера, куда нажать, чтобы проверить мой код.
> 4. **Связанные задачи** (Related issues) — плейсхолдер вроде `Closes #IssueNumber`.
